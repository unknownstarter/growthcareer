# Platform Evolution + Exhibition Rebranding Research (B0083)

> Echo, 2026-07-04. 1기 종강 (7/19) 임박 시점, "Fan to Pro 1기 모집 랜딩" 에서 "Growth Career 다기수 다트랙 curated 교육 브랜드 전시" 로 진화하기 위한 벤치마크 리서치. Aria (PO) + Sophia (PD) + Luna (UX) 후속 dispatch 용.

## Executive Summary

- 다기수 전시로 진화하는 부트캠프의 공통 패턴은 (1) verified outcomes 페이지 분리, (2) alumni network 를 core moat 로 노출, (3) 트랙별 landing 을 유지하되 상위 우산 브랜드 shell 를 통일. Lambda School / BloomTech 몰락의 교훈은 "발표 rate vs 실제 rate 괴리" 로 신뢰 무너지면 브랜드 자산 전부 소각됨. 우리는 CIRR 급 자체 표준 문서를 초기부터 박제해야 함.
- Vercel / Linear 를 참고한 다크 마케팅 톤은 개발자 대상엔 강력하지만 우리 타겟 (외국인 K-pop 지망생, 기술 배경 낮음) 엔 신뢰보다 진입 장벽이 될 위험. Toss 톤 라이트 LMS 는 유지하되, 마케팅은 "다크 유지 + 사람 얼굴/스토리 비중 확대" 로 재구성 권장.
- 외국인 특화 UX 는 언어 스위처보다 "비자·문화 진입 스토리" 자체가 콘텐츠. Le Wagon Tokyo 의 J-Find 비자 서사가 벤치마크 — 우리 E-7-1 / K-CORE / F-시리즈 스토리를 학생 인터뷰 형식으로 재구성 필요.
- 전시 요소 10종 카탈로그화 완료. Luna 후속 컴포넌트 spec 에 그대로 이관 가능.

## Q2. 부트캠프 vs 커리어 플랫폼 UX 차이

### 부트캠프 사이드 (Ironhack / Le Wagon / 코드스테이츠)
- **entry** = "다음 기수 신청 CTA" 가 first fold 절대 위치
- **hero** = 취업률 + 대표 hiring 회사 로고 wall
- **social proof** = 학생 스토리 3~5개 (동영상 or 인터뷰 카드)
- **커리큘럼** = 주차별 상세 아코디언
- **CTA** = 신청 (payment or interview 예약)

### 커리어 플랫폼 사이드 (Handshake / RippleMatch / 원티드)
- **entry** = "너의 goal 알려줘" onboarding funnel
- **hero** = "10x 인터뷰 확률" / 매칭 확률 지표
- **social proof** = 파트너 회사 수 (Handshake 17M 유저, RippleMatch 20x match odds)
- **커리큘럼** = 없음. 대신 job posting 검색 + 필터
- **CTA** = 프로필 완성 → 매칭

### 우리 = 하이브리드
- 부트캠프 (4주 교육) + 채용 연계 (JD 지원 → 인터뷰 → 오퍼) 이중 구조
- **결론**: 부트캠프 톤을 유지하되 hero 지표에 "취업률" 뿐 아니라 "비자 발급 성공률" + "1기 → 실제 공연 참여 %" 같은 우리 특화 KPI 추가. Handshake 식 goal-onboarding 은 지원 폼 (application) 안에서 이미 커버 중.
- 출처: [Handshake](https://joinhandshake.com/students/), [RippleMatch](https://ripplematch.com/)

## Q3. 외국인 타겟 특화 UX

### 발견
- 한국 코딩 부트캠프 중 외국인 특화는 소수: **Habsida** (영어 강의, JS/Java/UX), **WCoding** (Foreigner Package 12주). 대부분 한국어 온리.
- Le Wagon Tokyo 는 국가별 landing 에서 비자 서사를 콘텐츠화 → 학생 여정 스토리 (Shuxing 학생: 관광 → J-Find → 프로그래밍 → SRE 취업) 를 마케팅 자산으로 사용.
- 다국어 UX 원칙 (NN/G): "big stuff same, details differ" — 정보 계층은 동일, 문화 코드/예시/색 뉘앙스만 조정.
- 한국 e-commerce UX 관찰 (Anna Kim, Bootcamp Medium): 한국 유저는 "aesthetically pleasing, compact" 선호, 서구 유저는 "functionality, reviews" 우선. → 우리는 이중 타겟이라 balance 필요.

### 우리에게 적용
- 언어 스위처만으론 불충분. **비자 진입 스토리 (E-7-1 완화 / K-CORE / F-시리즈) 를 학생 케이스 인터뷰 형식으로 콘텐츠화** = Le Wagon Tokyo 벤치마크.
- 국적 다양성 표기: 국기 이모지는 정치·인식 이슈 (예: 대만 문제, 티벳) 있어 지양. 대신 "N개국 출신" 숫자 지표 + 이름 (원할 시) 표기.
- KO/EN 병기 시 EN 카피는 "Thanks for your interest" 톤 (메모리: feedback_email_reply_tone).
- 출처: [Le Wagon Tokyo J-Find](https://blog.lewagon.com/career/j-find-visa/), [Habsida](https://habsida.com/), [NN/G 국제 UX](https://www.nngroup.com/articles/international-usability-details-differ/), [Anna Kim Korea vs US e-commerce](https://medium.com/design-bootcamp/ux-design-lessons-from-e-commerce-platforms-in-korea-and-the-u-s-a089b1320cde)

## Q4. 다크 마케팅 톤 vs 라이트 LMS 톤 이중 유지

### 벤치마크
- **Vercel**: 다크 마케팅 (`vercel.com`) + 라이트/다크 스위칭 dashboard. Geist design system 공개. "pure blacks, pure whites, no accent" — 개발자 신뢰용. 2026-02 dashboard redesign 정식 rollout.
- **Linear**: 다크 uniformly. 마케팅과 대시보드 톤 통일. "story-driven hero + micro-animation" 이 벤치.
- **Stripe**: 라이트 uniformly. 신뢰 지표는 "signature purple gradient + weight-300 elegance". 우리 가이드 (그라데이션 금지) 와 상충 — 참고만.

### 우리에게 적용
- 현재 dual-tone (`/fan-to-pro/*` 다크 마케팅 + `/(lms)/*` 라이트 Toss 톤) 는 이미 ADR 0006 에 박제. 유지.
- **위험 신호**: 개발자 대상이 아닌 K-pop 지망 외국인이 다크 톤에 신뢰를 못 느낄 위험. Vercel/Linear 다크는 개발자에게 "high-signal aesthetic" 이지만 우리 타겟엔 "cold, hard-to-read" 로 읽힐 수 있음.
- **권고**: 다크 shell 유지하되 (1) 사람 얼굴/스토리 섹션 비중 확대, (2) 배경에 채도 낮은 warm accent (톤다운 오렌지/골드) 1가지 허용 검토 — 그라데이션 X 룰과 충돌 안 하도록 단색.
- 출처: [Vercel The New Side](https://vercel.com/try/new-dashboard), [Vercel Geist Colors](https://vercel.com/geist/colors), [Linear design analysis](https://getdesign.md/linear.app/design-md), [Landing trends 2026](https://www.saashero.net/design/landing-page-design-inspiration-2026/)

## Growth Career 적용 인사이트 (7건)

### Insight 1: 리브랜드가 아니라 우산 확장으로
Lambda → BloomTech 리브랜드는 사고 세탁으로 읽혀 오히려 신뢰 손상. 우리는 이미 "Growth Career 우산 + Fan to Pro 첫 트랙" 구조 결정. 리브랜드 아니라 **상위 shell 신설 + 트랙은 그대로 유지**. Fan to Pro 는 트랙명, growthcareer.xyz 는 우산 도메인. 카피에서 "Fan to Pro 브랜드" 라고 하지 말고 "Growth Career 의 Fan to Pro 트랙" 으로.

### Insight 2: 발표 지표 정의를 사전 문서로 박제
Lambda 사고 = "발표 취업률 vs 실제" 괴리 → 브랜드 붕괴. 우리 outcome 페이지 신설 시 **분모 정의를 문서로 사전 공개**. 예: "실공연 참여율 = 수료자 중 실제 유니온픽처스 공연에 배정된 인원 / 수료자 총 수" 처럼 raw fraction + 정의 문장 병기. CIRR 을 우리 자체 표준으로 채택 (한국 문맥 조정).

### Insight 3: 학생 서사가 최고의 마케팅 자산
Le Wagon Tokyo Shuxing 학생 서사 (관광 → J-Find → 프로그래밍 → SRE 취업) 는 광고 100편보다 강력. 우아한테크캠프도 alumni 자발적 velog/medium 후기가 검색 결과 대다수. 우리 = **1기 수료자 3~5명 인터뷰를 정식 콘텐츠로 발주**. 국적 다양성 + 비자 여정 + K-pop 산업 진입 스토리.

### Insight 4: 파트너 로고 wall = 우리 유일한 초기 신뢰 asset
Codesmith 의 Google/Amazon 로고 wall = "우리 학생이 여기 취업했음" 사회적 증명. 우리는 아직 채용 파트너 0. **초기 대체 asset = Union Pictures 공연 프로젝트 로고 + DEEPI + Dropdown** 3사 파트너십 자체를 hero 로 노출. B0072 이후 채용 파트너 로고 wall 확장.

### Insight 5: 다크 톤 유지하되 사람 얼굴 비중 확대
Vercel/Linear 다크는 개발자 신뢰용. 우리 타겟 (외국인 K-pop 지망) 엔 "cold" 하게 읽힐 위험. 다크 shell 은 유지 (LMS 라이트 톤과 대비로 브랜드 축 분리) 하되 **사람 얼굴 / 스토리 / 인터뷰 카드 비중을 대폭 확대**. 통계·카피 중심에서 "누가 어떤 여정을 지나왔는지" 중심으로.

### Insight 6: 다국어는 언어 스위처가 아니라 콘텐츠 축
외국인 특화 = KO/EN 병기가 아니라 **비자·문화 진입 서사 자체를 콘텐츠**. Le Wagon Tokyo 는 J-Find 비자 신설을 콘텐츠 시리즈로 판매. 우리는 E-7-1 완화 / K-CORE 신설 / F-시리즈 특혜 = 이미 리서치 자산 있음 (docs/reports/2026-07-04-lms-diagnosis-summary.md). **블로그 시리즈 + 비자 가이드 페이지 신설** 로 자산화. SEO + GEO 지원 (B0019).

### Insight 7: 카운트다운은 "실제 마감" 있을 때만
On Deck 카운트다운 = passive waitlist 를 live event 로 전환. 하지만 Flowjam 경고: 가짜 카운트다운은 신뢰 해침. 우리는 B0039 SSG cache 사고 이미 겪음. **2기 waitlist landing 은 (a) 실제 마감일 확정 후에만 카운트다운, (b) force-dynamic 유지** (§7 룰).

## Aria (PO) 넘길 gap (5)

비즈니스 임팩트 관점.

### 1. Outcomes 페이지 신설 (High 임팩트)
1기 종강 직후 outcome 페이지 필수. 분모 정의 사전 공개. Lambda 실패 방지 + 2기 conversion driver.
- **Why**: 신뢰 자산 = 채용/파트너 확장의 base. 없으면 파트너 회사 개척 시 근거 부족.

### 2. Alumni 커뮤니티 승격 (High 임팩트)
카톡 오픈채팅 (1기 운영) → 종강 후 정식 alumni 그룹 (Slack? Discord? 카톡?) 승격. Le Wagon Slack 24,000 이 lifetime asset.
- **Why**: "lifetime career support" 카피가 실제 커밋 가능해야. 이후 2/3기 학생 유입 시 alumni-driven 성장 loop.

### 3. Cohorts Showcase (Med 임팩트)
1기 = 카드 1개. 2기 시작 전 신설 시급. 스파르타 exhibition 아카이브 패턴.
- **Why**: 다기수 증거 = 첫 번째 신뢰 지표. 없으면 "새로 시작한 부트캠프" 로 읽힘.

### 4. 채용 파트너 개척 (Very High 임팩트, 중장기)
현재 채용 파이프라인 0 (Sophia 진단). Union Pictures / DEEPI 외 K-pop 관련 회사 5~10개 파트너십 확보 → 로고 wall + JD posting.
- **Why**: 이게 없으면 "교육 + 실공연 체험" 이상 진화 X. B0072 채용 스키마 병행.

### 5. Waitlist 승격 흐름 (Med 임팩트)
현재 DB status `next_cohort_interest` 존재 (B0039). Landing 페이지 신설 + email drip 캠페인 프레임.
- **Why**: 1기 마감 후 3개월 gap 동안 lead 축적 필요. Sample landing (On Deck 패턴) 로 conversion.

## Sophia (PD) 넘길 정보 구조 요구 (5)

정보 아키텍처 관점.

### 1. `/showcase` 경로 신설
현재 marketing 은 `/fan-to-pro/*` (트랙 landing) 만. 우산 브랜드 전시가 필요. 후보 IA:
- `growthcareer.xyz/` (우산 랜딩, 다기수 지표)
- `growthcareer.xyz/cohorts/` (기수 아카이브)
- `growthcareer.xyz/stories/` (학생 인터뷰)
- `growthcareer.xyz/outcomes/` (통계 + 감사)
- `growthcareer.xyz/tracks/` (트랙 카탈로그)
- `growthcareer.xyz/fan-to-pro/` (Fan to Pro 트랙 landing, 기존)
- `growthcareer.xyz/blog/` (콘텐츠)

### 2. Cohort URL 스킴
현재 cohort slug = 8자 nanoid (예약어 회피). Showcase 용 human-readable slug 추가 필요? 예: `/cohorts/fan-to-pro-1`.
- Trade-off: nanoid 유지 (LMS/보안) + human-readable alias (marketing/SEO). alias 테이블 신설 or slug 두 필드.

### 3. Content 계층 결정
Student stories = CMS 필요? 아니면 MDX 파일? Blog 도 동일 선택.
- 후보: (a) Sanity/Contentful 도입 (b) 프로젝트 안 MDX (c) Notion API. B0083 phase 2 결정.

### 4. Outcomes 데이터 소스
발표 지표 = DB query 실시간? 아니면 매기수 종료 시 감사된 snapshot?
- **권고**: snapshot 방식. 매기수 종료 시 outcome_report 테이블에 박제 → showcase 페이지에서 join. 실시간 노출은 조작 여지 (Lambda 교훈).

### 5. Multi-track 확장 시 shell 통일
Fan to Pro / 셰르파 심화 / 올인원 landing 각각. 공통 shell (nav / footer / CTA / hero 지표) 는 layout 에 통합. 트랙별 색/사진만 override.
- 후보: `app/[locale]/(marketing)/layout.tsx` 통합 + 트랙 폴더 sibling.
