## 1. 컨텍스트

- **파트너**: 코워크위더스(Cowork) — 한국 거주 외국인의 구직 서비스
- **제휴 구조**: Cowork 를 통해 유입돼 *수강료를 결제한* 유저당 **수강료의 12%** 를 Cowork 에 지급
- **Growth Career 의 첫 외부 마케팅 제휴 파트너** (향후 다른 파트너 확장 가능)
- 미팅 의제: Cowork 측에서 "트래킹 방법을 논의하고 싶다" 고 요청

### 현재 인프라

- Next.js 16 App Router · Vercel · 도메인 `growthcareer.xyz`
- **GA4** — `NEXT_PUBLIC_GA_ID = G-6N0R68CH0D` 전 페이지 PV/click/unique user 추적 중
- **Supabase `applicants` 테이블** — Apply 2-step 폼 제출 저장 (RLS 적용)
- **수강료**: 880,000원 (1기 기준)
- **결제**: 폼 제출 후 토스뱅크 계좌입금 (PG 미사용) → 입금 확인은 수동
- **1기 정원**: ~20명 (소규모)

## 2. 사용자 초기 가설

> "단순히 생각했을 때는 코드를 입력할 수 있게 하고, 해당 코드가 있는 수강생을 세면 될 것 같은데. 그걸 어떻게 공유할지에 대해서 말하는건가? 그리고 우리 GA4 에서 PV, 클릭, 유니크 유저와 같은건 추적하고 있지? UTM 심어서 링크를 주면 되나?"

**결론**: 사용자 직관(프로모코드 + UTM)이 정답에 가까움. 단 역할 분리가 핵심 — 아래 §4 참조.

## 3. 트래킹 스킴 비교 (Echo 리서치)

| 방식 | 정확도 | 구현 비용 | 정산 신뢰 | 비고 |
|---|---|---|---|---|
| **UTM only (GA4)** | 60-70% | 0 (이미 있음) | 낮음 | 광고차단·동의거부로 30-40% 손실 |
| **프로모코드** | 95%+ | 낮음 (폼 필드 1개) | 높음 | 유저가 직접 입력 = 의도 확정 |
| **클릭 ID (Cowork측 발급)** | 80% | 중간 | 중간 | 쿠키 만료/iOS ITP 영향 |
| **서버 포스트백 (S2S)** | 99% | 높음 | 매우 높음 | 오버엔지니어링 — 20명 규모엔 과함 |
| **하이브리드 (UTM + 코드)** | **95%+** | **낮음** | **높음** | **← 권장** |

### GA4 단독이 안 되는 이유

- 한국 광고차단 사용률 약 32.5% + iOS ITP + GDPR/PIPA 쿠키 동의 거부 → 30-40% 가 GA4 "unassigned" 로 빠짐
- 결제 확인 방식이 수동 입금이라 **폼 제출 시점에 referral 박제** 하는 게 정합성 우위
- GA4 는 funnel 가시성용 (클릭/PV/체류) — 정산 source of truth 아님

## 4. 권장 구조 (Phase 1)

### 역할 분리

- **프로모코드 (Supabase `applicants.referral_code` 컬럼)** = 정산 source of truth
- **UTM (GA4)** = funnel 분석 보조 (클릭/PV/체류시간 가시성)
- **GA4 단독 정산 절대 금지**

### 최소 viable 셋업

1. Cowork 전용 코드 발급 — 예: `COWORK10` 또는 1기 한정 `COWORK-S1`
2. Apply 폼 step2 에 **"추천 코드 (선택)"** 텍스트 필드 1개 추가
3. UTM 링크 병행 — `?utm_source=cowork&utm_medium=referral&utm_campaign=s1`
4. Supabase `applicants` 에 `referral_code`, `utm_source` 컬럼 추가
5. 정산 = `referral_code='COWORK10' AND payment_status='paid'` SQL 카운트 × 880,000 × 12%
6. 월말 Cowork 에 PDF/시트 1장 — `{기간, 코드, 결제확정 N건, 정산액}`

### 확장 시 (파트너 5개+)

Tapfiliate / Rewardful 같은 SaaS 검토. 지금은 불필요.

- **Growth Career 가 단독 source of truth** — 결제 확인 주체가 우리(토스뱅크 입금)

## 6. PIPA — 데이터 공유 범위

- 수강생 이름/연락처/이메일/비자 = **PII** → Cowork 에 공유하려면 PIPA §17 별도 동의 필요 (현 동의서 범위 밖일 가능성 높음)
- **안전 범위**: 집계 카운트 (`5명 결제, 528,000원 정산`) 또는 **해시 ID** (PIPA §28-2 가명처리)
- **권장**: 집계만 공유. 추가 데이터 요청 시 동의서 개정 + 법무 검토

### 공유 가능 vs 절대 금지 (한 눈에)

| 표시 OK | 표시 금지 |
|---|---|
| 클릭 수 (UTM) | 이름 |
| 신청서 제출 수 | 이메일 |
| 결제 확정 수 | 전화번호 |
| 환불 수 | 비자 정보·국적 |
| 정산 합계액 | 해시 안 된 user_id |
| 일자별 추이 | 결제 입금자명 |
| 가명/해시 ID + 상태 | 신청서 자유서술 답변 |

## 7. 공유 방식 스펙트럼 (사용자 컨펌 후 결정)

| 방식 | 구현 비용 | 실시간성 | 신뢰감 | 보안 표면 |
|---|---|---|---|---|
| **A. 월말 집계 리포트** (CSV/PDF 메일) | 0 | ✗ async | 중 | 0 |
| **B. 토큰 URL 대시보드** (로그인 X, 추측 불가 URL) | 낮음 (1-2일) | ○ live | 중상 | 좁음 |
| **C. 어드민 대시보드 + 인증** | 중 (3-5일) | ◎ live | 높음 | 중간 |
| **D. API 키 + Cowork 직접 pull** | 중 (2-3일) | ◎ live | 높음 | 좁음 |

### 미팅 제안 (3안 제시 → Cowork 선택권)

1. *"월말 집계 리포트 (CSV/PDF) 메일로 보내드리는 게 가장 빠른 시작점, 1기 운영하며 정합성 검증부터 합니다."*
2. *"신뢰 쌓이고 2기 또는 파트너 늘면 — 읽기 전용 파트너 대시보드 만들 계획이에요. 실시간 클릭·결제·정산 합계 다 보실 수 있게."*
3. *"중간 단계로 토큰 URL 형태로 1주일치 집계 페이지를 띄워드리는 것도 가능합니다."*

→ Cowork 가 실시간성 요구하면 C, 신뢰 OK 라면 A 로 시작. 통상 **A로 시작 → C로 자연스럽게 진화**.
